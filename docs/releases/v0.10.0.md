# V10 / 0.10.0 · 更多包装形态（花篮 / 花礼盒 / 抱抱桶 / 手提花袋 / 木条花箱）与两个新拍照场景

日期：2026-11-07。状态：本地实现与验证完成，随本轮推送并部署现有魔搭 Docker（实际结果见文末「线上部署」）。

## 这一版变了什么

用户提出「包装那个部分可以多做一些场景，比如一个花篮或者一个盒子；再调查一下更多场景，用 3D 模型」，随后明确授权消耗 Lux3D 积分（原话「3d费用没关系，积分是够的，可以多做一些去优化」）。本轮据此做三件事：

1. **包装/呈现场景从 3 种扩到 8 种**（「包装与花器」一栏）：
   - 原有：纸片包装、细口花瓶、宽口陶罐（外观不变，仍是程序化几何）。
   - 新增：**藤编花篮、花礼盒、抱抱桶、手提花袋、木条花箱**。
   - 换形态沿用原有流程：点选先预览 →「采用这个形式」→ 一次撤销可回退；每种形态各自保存支点/姿态/剪短长度，切回来不会打乱。
   - 新增形态的支点散布与最大倾角按容器类型单独约束（花篮 0.13m / 32°、礼盒 0.115m / 26°、抱抱桶 0.05m / 14°、手提花袋 0.07m / 16°、木条花箱 0.12m / 30°），花头从容器口探出，成品自动整理时把露在器口外的茎叶剪短。
2. **5 件 Lux3D 生成的花器真实 3D 模型接入**（2026-11-07 13:32–13:38，每件 20 积分，合计 **100 积分**；taskId 4815066 / 4815084 / 4815099 / 4815119 / 4815140）：
   - 全部真实生成、下载、贴图压缩（2048 PNG → 1024 JPEG；MR 512）并把 uint32 索引无损改成 uint16；raw 32.46MB → 6.43MB（19.8%），单件 0.79–2.44MB，三角面 24,418–41,304。
   - 运行时按包围盒缩放/水平居中/底面落地（`app/src/three/decor/vessel-load.ts`），同一形态只加载一次；**加载失败自动回退程序化容器**，不阻塞玩法。
   - 程序化花篮/礼盒仍保留为兜底（`basket.ts` / `giftbox.ts`）；花瓶/陶罐继续用程序化 Lathe。
3. **拍照场景从 3 个扩到 5 个**：「花店一角」（暖灰泥墙 + 木柜台 + 两层搁板与玻璃陶罐 + 干花 + 壁灯）与「庭院午后」（浅色石板台 + 低矮绿篱 + 木格栅 + 陶盆绿植 + 浅天空 + 柔和暖阳）。两者只在拍照/成品阶段显示，工作台阶段仍是素色台面。

配套改动：
- `docs/presentation-scene-expansion.md`（新）：包装形态 10 种、拍照场景 9 种的调研，含 Lux3D 20 积分/件的成本口径、程序化 vs GLB 的取舍、来源表与未核验说明。
- 相册「花材与制作记录」、AI 点评上下文改用中文形态名/场景名；`photo.scene` 新增两个 id 仍进入拍照签名。
- 成品自动整理的下部茎叶清理半径按新容器口径区分（花篮/花箱更宽，抱抱桶/花袋更窄）。

## 已知边界与未做

- **GLB 花器的缎带颜色不跟随作品丝带**：礼盒/抱抱桶的缎带是生成时的颜色；程序化礼盒会跟随 `doc.ribbon.colorId`。非纸包形态本来也没有丝带换色入口。
- **程序化兜底与 GLB 外观不一致**：加载失败时看到的是程序化容器（花篮/礼盒为手写几何，其余为简化截面）。
- 观感证据以 1366×768 截图为主：4K 导出、移动端窄屏、自由环绕到侧面时布景台沿落差、真实设备帧率本轮未单独验收。
- 生成模型的 minor 瑕疵：抱抱桶正面一条细长纸边翘起、背面浅色横带；木箱俯视底板有细透光缝（均非破洞，QA 已记录）。
- 容器仍是「摆设 + 支点约束」，没有花泥/内衬碰撞体、没有真实插入阻力；花环、玻璃钟罩、单支包装仍是候选（见调研文档 §3）。
- 新增拍照场景只在拍照阶段显示；场景不可漫游，工作台背景仍是素色台面。
