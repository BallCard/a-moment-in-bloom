# V0.7.3 发布说明（本地候选，未推送）

2026-11-06 晚。依据 [尺寸与接触诊断方案](../v7-size-contact-diagnosis.md)，解决用户反馈的 V7「花材偏大、还是会穿模」。**当前仅本地代码与证据，未 commit 之外的推送、未部署**；版本号仍 0.7.0，此为当时的本地阶段记录；后续接触修复与本轮合并，正式推送归入 [V8 / 0.8.0](v0.8.0.md)。

## 用户能感觉到的变化

1. **花材整体变小、比例更像真实手绑花束。** 默认尺寸从 V0.7 的原尺寸切到候选 b：花头比之前小 20%（玫瑰可见头宽 22.23cm → 17.79cm、郁金香 18.96 → 15.17cm），枝长同步缩短 12%，叶片收 15%；程序化花材整枝 ×0.88。候选 a（旧比例）与 c（更紧凑：花头 -30%、枝长 -15%）可通过地址栏 `?size=a|c` 对照。
2. **新增/拖动/复制/精调/缩放不再能把花插进别的花里。** 这些入口共用同一套「有效落位」约束：拖动时从上一有效位向目标扫掠，被挡就沿花头表面滑开，找不到空间就停在最近能放下的位置（会提示「顶住了」）；不是硬停，也不再一律往花束中心退。缩放时缩小永远允许，放大压到邻花会停在最近可放大的大小。
3. **接触层只处理小幅残余。** 花头用与朝向一致的椭球包络：核心严格避让，外缘允许按花材宽容度轻贴（主花 1.8cm、配花 2.8cm、绿叶 4.5cm）；多头花逐头计算；同枝多花头不再互相覆盖位移。花瓣级微小交叠仍是允许的（不是逐花瓣物理）。
4. **旧作品不会被悄悄改比例。** 存档记录 `sizeCandidate`：旧作品按原尺寸 a 读回，新作品用默认 b；打开相册时按作品自己的候选重新加载素材。

## 修复的关键问题

- 花头实测把**已经裁掉的茎/叶顶点**算进去：玫瑰曾被量成 36cm 高 / 中心 23.65cm / 半径 12.92cm（实际 13.18cm / 35.06cm / 11.17cm），并连带把上半段茎缩到 5.65cm、接触中心和选中环对不准。现在严格按渲染索引实测。
- 拖动时滑动候选会改高度，导致一次拖动能把花枝「长高」4–13cm；拖动改为锁高度。
- 缩放约束的循环让「缩小」也被拦下；改为缩小直接放行。
- 验证脚本 `v07-motion` 曾因射线被前枝遮挡认错被拖枝，把跟手移动误判成邻枝跳变；已按 `selectedId` 校正。

## 已知限制

- 25 种程序化花材没有分离花头，不能单独缩小花头，只能整枝等比缩。
- 包络重叠 ≠ 花瓣网格穿透深度；旧 6/12/20 枝样束配方本身就把花头摆得很近，只作压力用例，不代表玩法路径；样束未重排。
- 20 枝密集 fixture 在接触层 6cm 分离上限处仍剩 core 0.31cm；正常玩法依赖 placement 的核心避让兜底。
- 旧作品的「可撤销整理」入口未做（只保证不被静默重排）。
- 严格物理、茎/叶/包装纸穿插、逐花瓣碰撞仍不做。
- 默认候选 b 是审美候选，等用户看 `app/.verify/v07-size/contact-sheet-size.png` 后确认；代码断言只证明比例关系正确。
