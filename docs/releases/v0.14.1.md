# V14.1 / 0.14.1 · 修向日葵「明黄」整枝变黄

日期：2026-11-09。状态：本地修复与验证完成，作为 V14 线的补丁版本发布（见文末推送/部署结果）。

## 这一版回答的问题

用户反馈：花材架里的「向日葵 · 明黄」**整枝都是黄的**——花瓣、花心、花茎、叶片全被染成黄色，不像向日葵，希望重新生成。

检查后确认这不是 Lux3D 模型本身的问题：基色「柠檬」的原始贴图里花瓣黄、花心棕、茎叶绿，缩略图与 3D 都正常。问题出在**换色变体**上：

- 花材的配色变体不改模型，只在加载时按 HSV 色相窗口重映射贴图（`app/src/three/assets/recolor.ts`）。
- 窗口由 `scripts/flower_glb_pipeline.py` 的 `hue_window()` 按「基色色相 ±60°」自动生成。向日葵基色 `#f0cd5c` ≈ 45.7°，得到窗口 **[346°, 106°]**。
- 这个窗口一路扫进茎叶的绿色带（70°–170°）。向日葵贴图里叶片/花茎的色相约 70°–100°，于是它们和花瓣一起被重映射成黄色，整枝变黄；花心的棕褐色（20°–45°）也在窗口内，被推到金色。

同一原因还影响另外两条变体（此前没被单独反馈）：`daisy-cream`（奶油雏菊，窗口 [338,98]）与 `spray-chrysanthemum-2`（多头黄菊，窗口 [345,105]），它们的茎叶也被染成黄色。

## 修复

1. **管线窗口加绿色带保护**（`scripts/flower_glb_pipeline.py`）：新增 `FOLIAGE_HUE_BAND = (70, 170)` 与 `clamp_petal_window()`。花瓣窗口端点只有**深入**绿色带超过 20° 时才截断到 69° / 171°；只擦到带边缘的窗口（≤20°）保持原样，避免误伤花瓣本身。基色本身落在绿色带的（如 `rice-flower`）不截。
2. **重新生成清单**：`python scripts/flower_glb_pipeline.py manifest` 重算 53 条清单与 catalog，只有三条窗口变化，其余 50 条不变；`assetsVersion` 更新为 `2026-11-09.lux3d-recolor-fix`，浏览器会重新拉取清单。
3. **重渲染缩略图**：`thumbs --families sunflower,daisy,spray-chrysanthemum` 重画 3 张 160×190 静态图（`sunflower-1` / `daisy-cream` / `spray-chrysanthemum-2`）。
4. **没有新增生成**：模型 GLB、贴图、几何全部不动，不消耗 Lux3D 积分，也不需要重新走生成任务。

修复后：花瓣保持明黄、花茎与叶片恢复绿色、花心保留棕褐色调（仍比原色略偏金，见边界）；「柠檬」基色与另外 50 条配色不受影响。

## 已知边界

- 花心（深棕）仍在换色窗口内，会被重映射成偏金棕色；本轮只保证茎叶不再变黄，没有为花心单独做暗部保护（那需要改换色算法，影响面更大）。
- 其余花型沿用原窗口；只有上表三条变体改了窗口，未重渲染其他缩略图。
- 换色仍是「整窗重映射色相」，同一窗口内的明暗层次保留、色相差异会被抹平，这是 V9 以来既有的取舍。
