# V14 / 0.14.0 · 花材架提效、包装面板收敛、拍照完成体验

日期：2026-11-09。状态：本地实现与验证完成，随本轮推送并部署现有魔搭 Docker（部署与线上核验结果见文末）。

> 版本说明：0.13.0 已由并行的「拍照布景近景道具」一轮占用并发布（`3db43e9` / tag `v0.13.0`）。本轮的体验打磨改动在其之上，按版本约定记为 **V14 / 0.14.0**；新验证脚本相应命名为 `v14-*`。

## 这一版回答的问题

用户判断「现在已经有完整作品的骨架，下一轮最值得优化的是让人更容易做出好看的花，并愿意留下来再做一束」，并给出六项排序：花材架提效 → 包装面板收敛 → 拍照完成体验 → 委托跟上素材 → 作品展带人创作 → 真实体验稳定性。本轮按这个顺序落地；素材侧的并行工作（V13 近景道具）未并入本提交。

## 1. 花材架提效（最直接）

- **两列紧凑卡片**：1366×768 一屏从约 4 种提升到 **8 种**；缩略图用现有 53 张 160×190 静态图纯 CSS 裁切放大上半段（主花 126% / 配花 120% / 绿叶 110%，顶部对齐），花头更清楚，**零新增图片体积**。
- **名称搜索**（花名 / 花科键 / 配色名）+ **9 个色系筛选**（粉红橙黄白紫蓝绿其他，由 `entry.color` 转 HSL 归类），分类 × 色系 × 搜索可叠加，带结果计数与空态。
- **最近使用**：localStorage `bouquet.shelf-recent`，最多 8 条、最新在前、可点选再取花、可清除、刷新保留；每科选色记忆沿用原 `bouquet.palette-colors`。
- **颜色点只在选中后展开**：点花材卡 = 取花进入放置；按住拖拽落位保留；满 20 枝时底部常驻提示，再点只 toast。
- **「挑选花材 / 已有花枝」标签切换**：不再两个长列表同时堆叠；收起窄把手保留。
- **委托心愿标记**：读 `store.commissionId` + `commissionWishes()`，families / assetIds / kinds 任一命中给卡片角标，顶部一行「委托心愿：…」；自由模式无标记。

## 2. 包装面板收敛

- **先选形式，再出内容**：第一层是纸片 + 7 种花器共 8 项，每项带 **真实渲染小预览图**（同株 6 枝样束、同机位、只换形态，8 张共 311 KB；缺图时退回手绘器型 SVG）。
- **纸片按步骤只出该步控件**：摆纸 = 纸色/纸片列表/大小·转向·位置/固定·层级；叠包 = 左右叠包·握点收束；丝带 = 只出丝带；卡片 = 只突出收件人/正文/署名，其余折进「还想调一调」，展开可改。
- **花器分支**：无步骤条、无纸片专属控件；插花调整（点画面选枝 → 插深/拔高 1cm、剪短 2cm，一次一条撤销）+ 丝带 + 卡片。
- 保留「预览 → 采用这个形式 → 一次撤销」；右栏顶部独立说明当前阶段与这一步做什么。

## 3. 拍照完成体验

- **大取景预览成为主视觉**：1366×768 下预览 292×292（面板 366px 宽），预览与 `captureThumbnail()` 逐像素同一构图；保留距离/左右/上下、方形/竖幅、边框、自动整理。
- **8 个场景改成缩略图卡片**：由 `v14-scene-thumbs.mjs` 真实渲染 360px JPEG（`app/public/assets/scenes/`，8 张 11–22 KB）；切换后预览即时更新。
- **一键适配花束取景**：`three/photo-fit.ts` 只读读取花头世界坐标与镜头，复刻导出取景数学反算 `zoom/offset`；测试中预测 maxNdc≈0.55、花束约占画面 51%，花头全部在框内，之后仍可手调。
- **保存成功卡**：展示作品名（`AlbumEntry.name`）、照片缩略图、「继续创作」回摆花、「查看相册」。
- **性能修正**：预览从每 1.6 秒无条件重渲染并编码，改为画面签名变化驱动 + 220ms 防抖 + 首帧 80ms；页面隐藏暂停、恢复补拍、保存/导出前等 in-flight 拍完。实测**静止 4 秒捕获 0 次**（旧逻辑约 2–3 次），隐藏期间 0 次。
- **观感校准**：贺卡收小约 13%（22×30.9cm → 19×26.7cm）并加深纸边，让花束回到第一眼；暖白纸 `outer #e9d7bf → #dcc09c`，在米白台面与窗边背景里能看出折线与纸口。

## 5. 作品展带人创作

- 作品展从 4 件扩到 **6 件**：4 件 Lux3D 整束 + 2 件明确标注「工作台手作 · 逐枝搭配后拍摄」的成品（「旧木桌的午后」「给朋友的生日」）。
- 每件作品带 `palette`（真实 manifest 花材 9–10 枝 + 纸色/丝带/器型/拍照场景），卡片与详情页都有「用这个配色开始创作」；`?palette=<id>` 在 `createRoot` 前覆盖上次作品并清掉地址栏参数，进入即为可继续编辑的摆放阶段。

## 6. 稳定性与验收

- 花材架、包装、拍照、委托、作品展各有独立 Playwright 脚本（`app/scripts/v14-*.mjs`），均可在生产包 `vite preview` 上跑（委托脚本通过 App 暴露的只读调试入口读判定，不再依赖 dev 源码模块）。

## 已知边界与未做

- 花材缩略图是**纯 CSS 裁切**，康乃馨/芍药/向日葵等大花底部会略截；没有生成独立的「花头特写」静态图（需改 manifest 且约 +50 张图）。
- 拍照面板内容较长，1366×768 首屏能看到大预览与场景卡，「拍照存相册 / 成功卡」需要向下滚动；391px 只保证本面板不横向溢出，左右栏半透明叠压是既有布局。
- 一键适配的 zoom 受滑杆上限 1.3 限制，默认构图点一次约 51% 画面占比，不裁花头；要更满需放宽 `readPhoto` 上限。
- 场景缩略图是「6 枝样束 + 当前布景」的真实渲染，换布景/道具后需重跑 `v14-scene-thumbs.mjs`；缩略图 360px 只够卡片尺寸。
- 作品展起始作品布局是按 manifest 家族做的启发式摆位，不是逐件手工编排，个别组合会偏一侧。
- c4–c6 没有人物立绘，用姓氏字信笺代替；抱抱桶 GLB 自带缎带为固定色，不跟 `ribbon.colorId`（V10 既有边界）。
- 4K / 移动端真实设备帧率、弱网逐资源加载观感仍未验收；开发页曾出现一次空白后刷新恢复，未复现，不能归因为本轮引入。
