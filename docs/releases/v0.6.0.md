# V6 / 0.6.0 · 花间一刻

日期：2026-11-06。用户审阅 V5 后要求“推进 V6”，并追加把顶栏阶段栏与左栏心愿卡合并为居中节点状态栏。本次推送包含 P0-A、P0-B 与这次 UI 合并；P1-C / P1-D 未做。

## 可以体验的变化

- **居中节点状态栏**：制作阶段与委托心愿合并为画布顶部居中一条状态栏。自由制作只显示节点轨（当前实心、已完成带 ✓、悬停说明、空作品禁用包装/拍照）；委托模式同栏显示人物头像、来信标题、进度环、当前要求与 ‹ › 翻看，可展开完整来信（点栏外或 Esc 收起），交付后显示「已交付 · 达成 n/m」。原顶栏阶段切换与左栏心愿卡删除。宽度 < 1340px 自动改为两段式，不与放置提示、右侧工具重叠。
- **相册满额保护**：12 件满额时不再静默挤掉最早作品，改为拒绝保存并弹层说明「打开相册管理 / 下载备份 / 取消」。普通拍照、交付、接单前归档共用同一数量与容量检查；失败时工作台、旧照片与委托进度保留，不再假报成功；读取相册不再静默截断。
- **相册备份与恢复**：相册面板新增「下载备份 / 恢复备份」，包含照片、拍摄时的制作版本、封面、花材摘要、委托记录与回应，不含凭据。恢复前显示新增 / 重复 / 超额数量，重复按作品 ID + 照片 ID 判断，可「只加新」或「用备份替换同名记录」；超额、容量不足、格式损坏时停止写入并保留原相册，刷新后结果保持。
- **点评绑定照片**：点评带输入签名（花枝、包装/丝带/卡片、presentation、拍摄设置与实际机位）。只有签名一致才显示为「当前画面」点评；转镜头、换花、改纸、切场景、改画幅/边框/题名/构图会立即隐藏旧分数，迟到响应被丢弃。拍照入册、交付、接单归档时点评随照片保存，相册详情与重开照片都能恢复，同作品两张不同机位照片各自保留。

- `npx tsc --noEmit` → 0；`npm run build` → 0（主 JS 1,114.00 kB / gzip 304.80 kB，CSS 57.70 kB，仍有既有大包提示）。
- `npm run smoke` → **45/45**（本机 Chrome headless，1366×768）。
- `app/.verify/v6-album.mjs` → **40/40**：第 13 件被拒且 12 件旧作品逐项保持；满额接单/交付不假报成功；`Storage.setItem` 抛错注入后数据完整；备份→清空→恢复→刷新一致；重复恢复两种保留方式；超额停止写入；读取 13 条不截断；旧单图相册可读。
- `app/.verify/v6-review.mjs` → **81/81**：点评显示与模型/时间；转机位旧分失效；保存照片不清点评；相册详情与重开恢复；两机位 92/75 各自保留；迟到响应被丢弃；换花/改纸/场景/画幅/边框/题名/构图失效；500 失败后仍可保存重试；备份恢复带点评。**全部 `/api/review` 响应为 `page.route` 模拟，未真实调用魔搭或 DeepSeek**。
- `app/.verify/v6-statusbar-check.mjs` → **24/24**：居中、节点切换/禁用/完成标记、进度环与翻页、来信展开/Esc、交付状态、与提示条和右侧工具不重叠、1280 两段式、无页面脚本错误。
- 容量实测：480px JPEG 缩略图约 24–27 KB，20 枝 doc 约 7.2 KB，典型作品（6 照）约 231 KB；12 件×6 照完整相册约 2.74–2.78 MB，本机 Chrome 写入并刷新读回成功。据此不迁移 IndexedDB，换浏览器仍以写入失败提示 + 保留原相册兜底。

## 边界

- P1-C 未做：3/9/20 枝样束前侧背面与材质收口、目标机持续性能。
- P1-D 未做：真人首次试玩、三束展示候选与演示脚本。
- 点评失效按实际机位约 0.6° 取整，更小幅度的微动不会失效；前端取消请求只停止等待与展示，不代表上游停止计费；未覆盖多标签页并发、真实限流/超时重试、相册满额与点评同时发生的组合。
- 未存进相册的「当前点评」刷新后不恢复（点评属于照片，需从相册重开照片）；相册仍用 localStorage，未做跨浏览器配额验证。
- 名称/Logo 与介绍页的审美验收仍未完成。
